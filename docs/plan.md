# 계획과 확정된 결정

## 확정된 결정 (2026-10-21, 사용자가 이 대화에서 직접 답함)
1. **전환 시점과 목표:** 지금 CARLA로 전환한다. 화물을 배달하는 경로를 처음부터 끝까지 가는 데 필요한 **거의 모든 기능**이 CARLA에서 동작한다고 판단되면 그때 ETS2로 넘어온다. ETS2의 가상 컨트롤러 등 기존 도구는 그대로 둔다. (ETS2 복귀는 선택으로 둔다 — 제안이며 사용자가 따로 정한 것은 아님.)
2. **기능 순서(추천안 선택):** ① 차선 유지와 경로 명령(회전) → ② 속도 제어(앞차 따라가기, ACC) → ③ 신호 정지 → ④ 보행자·돌발 상황.
3. **CARLA 버전:** **0.9.16 + Python 3.12** (2026-10-21, 사용자가 이 대화에서 직접 답함. 처음에는 0.9.15로 정했으나, 0.9.15의 Windows 클라이언트가 Python 3.10까지만 지원하는 것을 확인한 뒤 변경. UE5 기반 0.10.0은 공식 권장 VRAM 16GB·디스크 130GB라 제외).
4. **코드 위치:** 새 폴더, 새 git, 새 GitHub 저장소(`CARLAUTOPILOT`, 비공개)의 별도 프로젝트.
5. **작업 장소:** 코드 작성과 컴퓨터(GPU)가 필요 없는 일은 다른 컴퓨터에서, 프로그램을 실제로 돌리는 것은 집 데스크톱(RTX 4070 SUPER)에서 한다.
6. **시간:** 평일 하루 4시간, 주 약 20시간.
7. **기존 코드 사용:** ETS2 프로젝트의 코드는 쓸 만하다고 판단되면 가져와도 된다. 새 프로젝트에 ETS2 데이터셋은 넣지 않는다(비상업적 연구용).
8. **원격 접속:** 집 데스크톱 원격 접속은 아직 설정되어 있지 않고, 필요하면 설정한다.

9. **트럭·고속도로로 방향 전환 (2026-10-23, 사용자가 이 대화에서 직접 답함):** 지금 실험(E: 고친 전문가로 다시 모은 데이터)을 마친 뒤 CARLA 쪽을 ETS2에 가깝게 옮긴다 — 트럭 차량, 높은 운전석 카메라, 고속도로와 차로 변경. ETS2에서 짧게 먼저 시험해 보는 것은 **보류**.
   - 확인한 사실(2026-10-23): CARLA 0.9.16 차량 목록에 **트레일러가 없다**(CHANGELOG에도 언급 없음). 트레일러가 회전 때 안쪽으로 따라 들어오는 움직임은 CARLA에서 연습할 수 없고 ETS2에서 다뤄야 한다. `vehicle.carlamotors.european_hgv`는 바퀴 6개 트럭(base_type truck). 모양·축거·최대 조향각은 소환해서 확인할 것(미확인).
   - 차로 변경 명령을 넣으려면 `core.Command`를 바꿔야 해서 사용자 승인이 필요하다(아직 묻지 않음).
10. **속도 개선 원칙 (2026-10-23, 사용자가 이 대화에서 직접 답함):** 학습 데이터를 원본과 똑같이 두는 방법만 쓴다(PNG 압축 약하게, 화면 창 끄기, 학습 이미지 캐시, 읽기 병렬 수). 그래픽 Low와 카메라 수 줄이기처럼 데이터가 바뀌는 방법은 쓰지 않는다. 각 방법은 시간과 결과(픽셀·라벨·손실 값 일치)를 함께 비교해 확인한 뒤 적용한다.

## 구현 현황 (2026-10-21, 이전 컴퓨터에서 직접 작성)
- 구현하고 테스트한 것(121개 통과, Python 3.14와 CPU PyTorch 기준): 공통 규격, `FakeEnv`, 제어(IDM·ACC, PID, 순수 추종, 안전 계층), 평가(로그, 지표, 집계, 보고서), 에피소드 저장과 데이터셋과 에피소드 단위 폴드, 경로 조건부 조향 모델(명령별 출력 머리)과 학습 루프, 기준 정책(`PathFollowPolicy`), 실행기, 표준 시나리오 8개(직진·회전을 이어 붙이는 `compose`와 회전 3번·신호등·정지 표지판·앞차가 있는 708 m 모의 배달 경로 `delivery_route` 포함, 무작위 시나리오는 red_light·stop_sign·route 종류도 지원; 횡단 보행자: 차선 복도 안의 보행자를 앞 장애물로 보고 감속, 정지 표지판: 정지선 앞 8 m 안에서 0.5 m/s 이하로 멈추지 않으면 감점 포함), 명령줄, 환경 점검(`python -m carlautopilot.cli.check_env`), 주행 기록 그림(`python -m carlautopilot.cli.plot --log-dir <logs> --out-dir <png>`: 궤적·속도·횡오차·이벤트), 의사 카메라 렌더링, 데이터 수집기, `ModelPolicy`, 무작위 시나리오, 모의 환경 전 과정 시험(`python -m carlautopilot.cli.dryrun --work-dir <빈 폴더>`: 수집→학습→보유 시나리오 폐루프 평가). 참고: 학습 에피소드 14개로는 직진도 이탈했고 36개(샘플 약 3.5천, 12 에폭, CPU 약 3분)에서는 보유 12개 시나리오가 모두 완주했다(모의 환경이라 파이프라인 검증일 뿐 실제 성능이 아님).
- 기준 정책은 `FakeEnv`의 특권 정보(앞쪽 경로점, 신호등 상태)를 쓰므로 영상 모델이 아니다. 파이프라인과 평가 틀이 동작하는지 확인하는 용도다.

  - **트럭 데이터와 카메라 두 방식 (2026-10-24):** 한 번의 주행으로 두 카메라 묶음을 함께 모았다(`--rigs 120:0,90:25`): ① 시야각 120°, ② 회전 명령 방향으로 초당 25°씩 최대 25° 도는 카메라(라벨은 같음). 4개 도시 각 17개, 68개(67 완주, 1 정체), PNG 압축 1, 창 끔. 에피소드당 약 2.9분(카메라 10대). ResNet18을 각각 학습(캐시 + 병렬 0, 91.1분 / 85.4분 — 캐시 생성 포함, 예상보다 길었음).
  - **결과(트럭, 조향만 학습, 속도는 규칙):** 시야각 120° Town03 36% 완주 1/8, Town02 56% 2/10. **회전 카메라 Town03 59% 완주 3/8, Town02 44% 3/10.** 완주 합계 3/18 대 6/18. 회전 구간 실패는 13건 → 5건으로 줄었다(좌회전 8 → 1). 대신 회전 카메라 모델은 일반 주행 실패가 7건(시야각 120°는 2건)이고 일반 주행 |횡오차|가 0.35 m(0.16 m)로 컸다. 일반 주행 실패는 교차로 직후에 몰려 있지 않아 "카메라가 돌아오는 중" 가설은 맞지 않았다. 원인 미확인. 평가 경로 18개, 학습 1회라 차이 일부는 우연일 수 있다.
  - 규칙과 학습의 구분: 모델은 조향만 배웠다. 속도는 ACC와 교차로 감속 규칙이다. 다음 단계로 속도도 모델이 정하게 바꿔야 한다.
  - VRAM 측정(배치 64, 128×256): 작은 CNN 140 MB, ResNet18 1.1 GB, ResNet18+AMP 750 MB(배치당 76 ms). CARLA를 켠 채(약 8 GB) 학습할 수 있다.
  - 시험으로 찾은 것: 같은 프로세스에서 맵을 바꾸면 클라이언트가 간헐적으로 강제 종료됨 → 별도 프로세스로 전환.
- 시험으로 찾은 것: 지표의 완주율이 환경의 완주 판정과 어긋나 있어서(경로 끝 1 m 전 허용) `route_complete`로 끝난 에피소드는 완주율 1.0으로 정의를 고쳤다. 안전 계층은 앞차가 100 m 안에 보일 때만 반응하므로 속도가 너무 높으면 제동 거리가 모자랄 수 있다(시험에서 확인).
- 의도적으로 변이 시험(코드를 일부러 망가뜨려 시험이 잡는지 확인)을 한 항목: 조향 부호, 신호 위반 판정, 신호 정지 로직, 순수 추종 부호, 안전 계층.

## 아직 확정되지 않은 것
- **"자율주행이 가능하다"의 통과 기준:** 정해진 시나리오 세트(직진, 좌우회전, 앞차 따라가기, 신호 정지)에서 경로 완주율과 충돌·신호위반 횟수로 판단하는 것을 제안했다. 구체적인 수치는 첫 결과를 본 뒤 사용자와 정한다.
- **배달 경로에 필요한 기능의 범위:** 고속도로, 회전교차로, 차선 변경, 목적지 정차 등을 어디까지 넣을지.
- **ETS2로 돌아갈지 여부와 시점.**

## 확인이 필요한 사실 (미확인)
- 공식 문서(0.9.15 빠른 시작, 확인함): VRAM 최소 6GB·권장 8GB, 디스크 약 20GB, 포트 2000과 2001, pip 20.3 이상.
- PyPI의 Windows 클라이언트 휠(2026-10-21 직접 확인): 0.9.15는 3.7~3.10, 0.9.16은 3.10~3.12. 3.13 이상을 지원하는 버전은 없다. 0.9.16 Windows 패키지 안에도 cp312 휠이 들어 있다.
- 확인함(2026-10-21): 동기 모드, 카메라, 충돌 센서, Traffic Manager(동기 모드)로 다른 차량 운행, `GlobalRoutePlanner`로 경로 생성. 전문가 데이터는 Traffic Manager 자동 주행 대신 정답 정보를 쓰는 우리 전문가(`PathFollowPolicy`)로 만들었다(조향 라벨을 프로젝트 규약으로 바로 얻기 위해). 시나리오 실행기(ScenarioRunner)는 아직 쓰지 않았다.
- 데스크톱 설치 결과(2026-10-21 직접 확인): Python 3.12.10을 기본 3.13과 나란히 설치, 저장소 안 `.venv`(3.12)에 requirements, torch 2.14.1+cu132, carla 0.9.16 설치. `torch.cuda.is_available()` 참, 테스트 120 통과·1 건너뜀(CUDA가 있으면 건너뛰는 테스트). CARLA 서버는 `D:\CARLA\CARLA_0.9.16`, 서버·클라이언트 모두 0.9.16으로 연결 성공, `check_env` 전 항목 OK.
- 첫 서버 실행은 연결을 받기까지 5분 넘게 걸렸다. Epic 품질에서 VRAM 약 9.1GB, GPU 96%를 써서 학습과 동시에 돌리려면 낮은 품질이나 `-RenderOffScreen`을 시험해야 한다(미확인).
- CARLA의 기본 자동 주행 데이터는 사람보다 깔끔해서 학습 성능이 과대평가될 수 있다. 결과에 이 한계를 명시한다.
