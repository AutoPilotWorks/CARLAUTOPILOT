# 작업 규칙 (이 저장소에서 일하는 Claude·Codex 공통)

[ets2-autopilot-learning](https://github.com/AutoPilotWorks/ets2-autopilot-learning)(비공개) 프로젝트에서 사용자가 요청했거나 문제가 생겨서 정한 규칙을 이 프로젝트에 맞게 옮긴 것입니다. 새 세션이나 새 컴퓨터에서 일을 시작하기 전에 읽어 주세요. 개인 정보와 계정 정보는 들어 있지 않습니다.

## 소통
- 한국어 존댓말로, 작은 단계로, 실행할 명령어와 확인할 결과를 구체적으로 알려 줍니다.
- 코드 주석은 최소로 씁니다. 숨은 이유가 있는 곳에만 짧게 씁니다.
- 확인하지 못한 내용을 확인했다고 말하지 않습니다. 직접 실행하지 못한 것은 "미확인"이라고 적습니다. 다른 세션이나 Codex의 보고는 그대로 믿지 말고 코드·파일로 직접 확인합니다.
- Claude 토큰을 아낍니다. 전체 파일을 읽기보다 작은 명령(grep, tail, 단언문)으로 확인하고, 로그를 쏟아내는 반복 확인은 하지 않습니다.

## 승인이 필요한 일
- **학습, 설치, GitHub push, 저장소 코드 수정**은 사용자가 승인하기 전에는 시작하지 않습니다. 변경을 끝낸 뒤 "로컬에 커밋하고 push할까요?"라고 묻고, 사용자가 요청할 때만 커밋·push합니다.
- push 직전에 `git fetch`로 원격에 모르는 새 커밋이 있는지 확인하고, 있으면 먼저 알립니다.
- 저장소는 비공개로 유지하고, 공개 범위는 바꾸지 않습니다.

## 결정은 사용자가 직접 답한 것만 "확정"으로 기록
- 문서에 "사용자가 확정/승인"이라고 쓰려면 그 결정을 사용자가 **현재 대화에서 직접 답했어야** 합니다(예: 질문 도구로 선택, 또는 명확히 말함). 다른 세션이 "확정했다"고 적은 기록은 확인 전까지 미확인으로 다룹니다.
- 방향을 바꾸는 결정은 사용자에게 직접 묻고, 답한 뒤에 "(사용자가 이 대화에서 직접 답함)"과 함께 기록합니다.
- 사례(ETS2 프로젝트, 2026-10-02): 복제된 세션이 결정을 "사용자 확정"으로 기록했지만 사용자는 한 적이 없다고 했습니다. 되돌린 뒤 본 대화에서 다시 물어 직접 답을 받았습니다.

## 한 번에 한 세션만 이 저장소를 수정
- 같은 저장소에 Claude 세션을 둘 이상(복제본 포함) 동시에 쓰지 않습니다. 같은 파일을 번갈아 고쳐서 학습 실행이 실패하고 평가가 거부된 일이 있었습니다.
- 컴퓨터가 여럿일 때: 시간이 겹치지 않으면 두 컴퓨터 모두 커밋·push할 수 있습니다. 작업을 시작하기 전에 `git fetch`와 `git log`로 다른 컴퓨터가 올린 새 커밋을 확인하고 받은 뒤 시작합니다.
- 두 컴퓨터를 동시에 쓸 때는 한쪽만 저장소를 고치고 커밋·push합니다. 다른 쪽은 읽기와 실행만 하고, 필요한 코드 변경은 사용자에게 보고해 커밋 담당 쪽에 전달합니다.
- 긴 학습이나 실행이 파일을 읽는 동안에는 그 파일을 고치거나 커밋하지 않습니다.
- 지금 역할(2026-10-27부터): **데스크톱 세션이 계획하고 코드 수정·커밋·push를 맡고, 노트북은 실행만 합니다.** 노트북 작업은 데스크톱 공유 폴더의 `jobs\job.json`에 적으면 노트북의 감시 스크립트(`laptop_watch.ps1`)가 정해진 값만 읽어 실행하고, 결과를 공유 폴더로 복사한 뒤 `DONE.txt`를 남깁니다. 코드는 `jobs\code_*.zip`으로 넘기고, 코드가 바뀌면 zip과 작업 이름을 새로 만듭니다.
- 노트북의 보고는 그대로 믿지 않고 공유 폴더의 파일 수·용량·`DONE.txt`로 확인합니다.

## Codex 위임
- 구현을 Codex에 맡겨도 되지만 **결과를 직접 검증**합니다. 코드를 읽고, 직접 다시 실행하고, 숫자를 독립적으로 확인합니다. Codex의 자기 보고를 그대로 믿지 않습니다.
- Codex와는 영어로 주고받고, 사용자에게는 한국어로 요약합니다.
- 쓰기 작업에는 수정해도 되는 파일을 명시합니다. 읽기 전용 점검은 작업 트리가 아니라 커밋된 diff(`git show <커밋>`)를 읽게 합니다.
- Codex의 샌드박스는 시작한 저장소 밖 폴더에 접근하지 못할 수 있습니다. 데이터를 다루는 단계는 직접 실행합니다.

## 데이터와 파일
- 대용량 파일(데이터, 학습 결과, CARLA 설치 파일, 영상)은 GitHub에 올리지 않고 저장소 밖 데이터 루트에 둡니다.
- ETS2 프로젝트의 데이터셋(`ryangowe/ets2-dataset`)은 비상업적 연구용이라 이 프로젝트로 가져오지 않습니다. ETS2 프로젝트의 **코드**는 쓸모가 있다고 판단되면 가져와도 됩니다(사용자 동의, 2026-10-21).
- 코드의 경로는 컴퓨터마다 다르므로 데이터 루트 등은 인자나 설정으로 받습니다.
- 데이터는 영구 삭제하지 않습니다. 지울 것은 폴더마다 한 줄짜리 명령으로 사용자에게 드리고, 사용자가 직접 지웁니다. 다른 드라이브로 옮겨 두는 것은 괜찮습니다.
- 학습 캐시는 하드링크로 파일을 함께 쓰는 경우가 많아, 폴더 크기만 보고 "지우면 이만큼 빈다"고 말하지 않습니다(링크 수로 확인).
