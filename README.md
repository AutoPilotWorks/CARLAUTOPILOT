# CARLAUTOPILOT — CARLA 기반 영상 자율주행 연구

CARLA 시뮬레이터에서 **영상으로 판단하는 자율주행**을 만들고, 거의 모든 기능이 동작한다고 판단되면 Euro Truck Simulator 2(ETS2)로 옮기는 프로젝트입니다. 최종 목표는 화물을 배달하는 경로를 처음부터 끝까지 스스로 주행하는 것입니다.

## 현재 상태 (2026-10-29, 집 데스크톱)
- **최고 기록은 v1.10c, 48개 경로 중 31개 완주입니다.** 트럭이 운전석 카메라만 보고 조향, 목표 속도, 빨간불·정지선·정지 표지판·양보·앞차를 스스로 판단합니다. 평가에는 정지 표지판과 교차로 양보 규칙도 들어 있습니다.
- **남은 가장 큰 실패는 빨간불 위반(39회)과 도로 이탈(14회)입니다.** 빨간불 위반의 31회는 학습하지 않은 Town02에서 나왔습니다.
  - 원인을 추적한 결과, 신호등 카메라(40°, 위로 10°)가 Town01·02의 낮은 기둥 신호등을 정지선 20 m 안쪽에서 화면 밖으로 놓치고 있었습니다.
  - 6개 도시의 정지선 313곳을 계산해 신호등 카메라를 **50°, 위로 5°**로 바꾸기로 했습니다.
  - 그 카메라로 학습 데이터를 다시 모으는 중입니다(v1.11). Town04를 학습 도시에 새로 넣고, 빨간불로 다가가는 장면을 더 자주 학습합니다.

## 지나온 길
1. **환경과 첫 모델 (10-21):** CARLA 0.9.16 어댑터, 경로 계획, 전문가(정답 정보를 쓰는 규칙 운전자)를 만들었습니다.
   - 작은 CNN은 한 경로도 완주하지 못했습니다. 사전학습 ResNet18로 바꾸자 처음 완주가 나왔습니다.
   - 평가 쪽 문제 두 가지를 고쳤습니다. 회전 속도가 전문가와 맞지 않았고, 출발 직후 차로를 바꾸는 경로가 섞여 있었습니다.
2. **전문가와 카메라 다듬기 (10-22~24):**
   - 전문가가 회전 안쪽을 잘라 먹고 있어서 시선 거리를 줄였습니다.
   - 시야각 90°에서는 T자 교차로의 꺾일 길이 화면 밖이었습니다. 시야각 120°와, 회전 명령 방향으로 도는 카메라를 비교했습니다.
   - 차량을 트럭(`european_hgv`)으로 바꿨습니다. 데이터는 그대로 두고 속도만 올리는 방법(PNG 압축, 창 끄기, 캐시)을 적용했습니다.
3. **두 카메라를 합침 (10-26):** 시야각 120°에 회전 카메라를 더한 v1.6이 23/48을 완주했습니다. 이때 속도와 신호는 아직 규칙이었습니다.
4. **규칙을 모델 판단으로, 1단계 (10-26~27):** 목표 속도(v1.7)와 신호·정지선·앞차(v1.8)를 학습했습니다. 지름길 두 개를 찾아 고친 v1.8e가 24/48로 처음 규칙 기반을 넘었습니다.
5. **2단계: 정지 표지판과 양보 (10-27):** 2단계 전문가는 Town03 8/8, Town02 10/10을 완주했습니다. 모델 v1.9e는 정지 표지판에서 영영 서 버리는 문제가 남았습니다. 사진 한 장으로는 "이미 멈췄는지"를 알 수 없기 때문입니다.
6. **정지 원인 분리와 신호등 카메라 (10-27~28):** 정지 이유를 빨간불, 정지 표지판, 양보로 나눴습니다.
   - 정지 표지판에서 1초 서는 것은 규칙으로 했습니다.
   - 좁은 신호등 카메라를 따로 달았고, 세 번째 지름길을 고쳤습니다.
   - 데스크탑과 노트북이 함께 모은 204개 주행으로 학습한 v1.10c가 31/48을 완주했습니다.
7. **Town02 빨간불 추적 (10-28~29):**
   - 평가 기록에 모델 판단과 실제 신호를 남기고, 사건 직전 화면을 저장하게 해서 원인을 좁혔습니다. 정지선 거리를 멀게 보고, 낮은 신호등이 화면 밖으로 빠지고 있었습니다.
   - 신호등 카메라를 다시 정했고, 새 카메라로 데이터를 다시 모으는 중입니다(v1.11).

**지금까지 찾아 고친 지름길과 맹점.** 같은 종류의 실수가 반복돼서 모아 둡니다.
1. 카메라에 차체가 찍혀 정답이 새어 나감(v1.8a, 5/48) → 카메라를 차체 밖(x=4.1)으로 옮김
2. 인식이 속도 입력에 기대 "서 있으면 정지"를 배움(v1.8d, 14/48) → 인식은 이미지만으로(`--percept-from-image`)
3. 빨간불을 신호등이 아니라 "정지선이 보이면 빨간불"로 맞힘(v1.10, 신호등 영상을 지워도 정답률 그대로) → 빨간불은 신호등 영상에서만
4. 신호등 카메라가 낮은 신호등을 못 찍음(v1.10c, Town02 위반 31회) → 정지선 313곳 계산으로 50°/위 5° 선택

교훈: 학습 결과가 좋아 보여도 **모델이 무엇을 보고 판단하는지**를 입력을 지우거나 바꿔 가며 확인하고, 센서가 무엇을 찍는지 직접 봐야 합니다.

## 코드를 돌려 보는 법
```bash
python -m pytest -q
python -m carlautopilot.cli.evaluate --out-dir <새 폴더> --title "Baseline"
```
CARLA 서버(`CarlaUE4.exe -RenderOffScreen`)를 켠 뒤, 지금 쓰는 설정입니다.
```bash
python -m carlautopilot.cli.carla_run collect --carla-root <CARLA 폴더> --data-root <데이터 폴더> --town Town03_Opt --episodes 17 --seed 61 --stride 4 --views "1:0,-1:0,0:10,0:-10" --rigs "120:25" --png-compress 1 --vehicle truck_cab --image-size 160x320 --walkers 40 --junction-rules --start-delay 2 --light-camera 50:5:160x320
python -m carlautopilot.train.train_steering --data-root <데이터 폴더> --out-dir <학습 폴더> --cache-dir <캐시 폴더> --device cuda --num-workers 4 --epochs 8 --batch-size 64 --backbone resnet18 --lr 3e-4 --amp --loss-weights 10 0.5 0.5 0.5 1 0.2 0.05 1 0.05 0.05 0.1 --predict-speed --perceive --percept-from-image --split-stops --balance-stops --boost-red-approach 3 --light-camera
python -m carlautopilot.cli.carla_run eval --carla-root <CARLA 폴더> --town Town02_Opt --episodes 10 --seed 100 --vehicle truck_cab --image-size 160x320 --walkers 40 --junction-rules --fov 120 --turn-camera 25 --model-speed 8 --light-camera 50:5:160x320 --event-frames --checkpoint <학습 폴더>/checkpoint.pt --out-dir <평가 폴더>
```
- `eval`에 `--checkpoint`가 없으면 전문가를 평가합니다. 한 번에 도시 하나만 다룹니다(맵 전환은 별도 프로세스, 이유는 architecture.md).
- 평가 기록(`logs/*.jsonl`)에는 프레임마다 모델의 인식 출력(`percept`)과 다음 신호의 실제 거리·상태(`truth.next_light_m`, `next_light_red`)가 남습니다. `--event-frames`를 주면 사건 직전 4초 화면이 `frames/`에 저장됩니다.
- 설치: Python 3.12 가상환경에 `requirements.txt`, CUDA용 `torch`·`torchvision`(pytorch.org의 cu132 인덱스), `carla==0.9.16`, `networkx`.

## 확정된 결정 요약 (상세는 plan.md)
- 지금 CARLA로 전환하고, 배달 경로 전체에 필요한 거의 모든 기능이 되면 ETS2로 넘어온다.
- 기능 순서: 차선 유지와 경로 명령 → 속도 제어(ACC) → 신호 정지 → 보행자·돌발 상황.
- CARLA 0.9.16 + Python 3.12, 새 저장소(비공개), 집 데스크톱(RTX 4070 SUPER)과 노트북(RTX 5060 Laptop)을 함께 쓴다.
- 규칙은 땜질하지 않고 모델 판단으로 바꾼다(1단계 신호·앞차, 2단계 정지 표지판·양보). 3단계는 하지 않는다.
- ETS2 프로젝트의 코드는 쓸 만하면 가져온다. ETS2 데이터셋은 비상업적 연구용이라 가져오지 않는다.

## ETS2 프로젝트에서 이어받는 것
이전 프로젝트 [ets2-autopilot-learning](https://github.com/AutoPilotWorks/ets2-autopilot-learning)(비공개, 소유자만 접근 가능)에서 얻은 것을 **그 저장소의 2026-10-19 인계 문서 기준으로 요약**한 것입니다. 이 저장소에서 다시 검증하지 않았습니다.
- **목표 철학(사용자, 2026-10-19 ETS2 문서):** 화면만 보고 AI가 스스로 판단하는 자율주행을 만든다. 따라 하기와 규칙 덧대기로 끝내지 않고, 규칙은 하나씩 걷어내며 "모델만"으로 매번 측정한다. ACC처럼 실제 차를 흉내 낸 공학 모듈은 섞어도 되지만, 따로 떼어 나중에 학습으로 바꿀 수 있게 만든다.
- **실패에서 배운 것:** 10월 14일 벽 충돌의 원인은 모델이 아니라 **차선 보조 규칙**이 엉뚱한 선을 잡아 모델의 조향을 뒤집은 것이었다. 규칙을 넣으면 그 규칙이 오류의 원인이 될 수 있다.
- **평가에서 배운 것:** 라벨 정의가 겹치면(감속과 정지) 모델 한계처럼 보이는 오류가 생긴다. 세션 단위 교차검증과 단순한 기준선(속도만 쓰는 결정트리)과의 비교가 필요하다. 신호등을 학습으로 바꾼 시도는 손으로 만든 색 규칙보다 성능이 낮았다(0.71 대 0.78).
- ETS2 프로젝트에서 쓸 만한 코드(ACC, 안전 계층, 평가 도구 등)는 필요할 때 골라서 가져온다.
