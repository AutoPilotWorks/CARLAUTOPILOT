# CARLAUTOPILOT — CARLA 기반 영상 자율주행 연구

CARLA 시뮬레이터에서 **영상으로 판단하는 승용차 자율주행**을 만드는 프로젝트입니다. 차량은 링컨 MKZ 2020(CARLA Leaderboard 2.0과 Bench2Drive가 쓰는 차)입니다. 처음에는 CARLA에서 기능을 만든 뒤 Euro Truck Simulator 2로 옮길 계획이었지만, 2026-10-30에 그 계획을 접고 CARLA 세단을 본 프로젝트로 정했습니다.

## 현재 상태 (2026-11-17 정리, 마지막 실험 11-02, 집 데스크톱)
- **세단 최고 기록은 v2.1 A, 48개 경로 중 20개 완주입니다.** 목표는 A ≥36/48, 최종 ≥39/48(80%)입니다.
  - 트럭 실험은 v1.13(35/48)에서 마쳤습니다. 결과는 아래 표에 남겨 둡니다.
- **세단 첫 평가(6단계)에서 실패 원인 세 가지를 측정으로 찾았습니다.**
  1. 차로 이탈: 전문가가 늘 차로 한가운데로 달려서, 벗어났다가 돌아오는 장면이 데이터에 없습니다.
  2. 가까운 물체: 0~4 m 앞 물체를 12%만 봅니다. 보닛 아래가 카메라 사각입니다.
  3. 빨간불: 전문가가 늘 정지선 7.2 m 앞에 서서, 모델이 "멈췄으면 7 m"로 배워 조금씩 앞으로 미끄러집니다. 정지선 2~4 m 안에서는 학습에 없던 장면이 되어 신호를 놓칩니다.
- **원인별 수정을 코드에 넣었습니다(이 커밋).** 복구 시점 카메라, 정지 위치 무작위화, 경로 보행자, 앞차 급정거, 전면 레이더와 카메라 융합입니다. 아래 "지나온 길" 11~12를 보세요.
- **새 데이터(v2.2)는 아직 학습하지 않았습니다.** 수집 중에 버그 두 개가 나왔습니다.
  - 전문가가 폭 2.6 m가 넘는 차(버스, 소방차, 트럭)를 차로 한가운데에서 앞차로 보지 못했습니다. **고쳤습니다.** 예전 데이터(v2.0, v2.1)에도 같은 문제가 있었을 수 있습니다.
  - 앞차 급정거 차가 다시 출발할 때 Traffic Manager 설정이 풀려 시속 60 km까지 가속하고, 그 뒤 수집 프로그램이 같이 죽습니다(Town05에서 매번 재현). **아직 고치지 않았습니다.**
- 상세는 [docs/handoff_2026-11-17.md](docs/handoff_2026-11-17.md)에 있습니다.

학습 라벨을 만드는 전문가는 정답 정보를 쓰는 규칙 운전자입니다.

## 지나온 길
1. **환경과 첫 모델 (10-21):** CARLA 0.9.16 어댑터, 경로 계획, 전문가(정답 정보를 쓰는 규칙 운전자)를 만들었습니다.
   - 작은 CNN은 한 경로도 완주하지 못했습니다. 사전학습 ResNet18로 바꾸자 처음 완주가 나왔습니다.
   - 평가 쪽 문제 두 가지를 고쳤습니다. 회전 속도가 전문가와 맞지 않았고, 출발 직후 차로를 바꾸는 경로가 섞여 있었습니다.

    - 차로 이탈 → 복구 시점 카메라(`--views`): 전면 카메라를 좌우 1 m 옮기고 좌우 10° 돌린 영상 4장을 같이 찍고, 전문가가 그 자리에서 낼 조향을 정답으로 답니다. 렌더링은 2배 해상도로 해서 4배와의 차이가 화소 평균 1.21/255였고, 수집이 약 2배 빨라졌습니다.
    - 가까운 물체 → 전면 레이더(`--radar`)와 카메라의 늦은 융합, 경로 보행자(`--path-walkers`: 차로 가장자리를 걷거나 앞을 건너는 보행자), 앞차 급정거(`--lead-brakes`). 앞차가 8 m 안에 있으면서 움직이는 장면이 0.3%에서 2.55%가 됐습니다.
    - 빨간불 미끄러짐 → 정지 위치 무작위화(`--light-stop 1.5:8`, 주행마다 정지선 1.5~8 m 앞).
    - 레이더 확인 시험: 측정 지연 5 ms 이하, 접근 속도 부호 정상. 20 m 안 포착률은 Town02 차량 98%·보행자 92%였지만 Town03 차량 0~46%, 보행자 6~65%였습니다. 시야각 30°가 좁아 2 m 앞에서 좌우 ±0.5 m만 봅니다. 레이더 보완은 승인 대기입니다.
13. **v2.2 수집 (11-02):** 데스크탑 87개 주행 중 완주 64개(73.6%)로 기준 90%에 못 미쳤습니다(Town01 23/40, Town03 34/40, Town05 7/40). 위 "현재 상태"의 버그 두 개가 원인이고, 학습은 하지 않았습니다.
    - 노트북(Town04·10HD × 40, 급정거 없음)은 수집 기록상 80개 중 완주 73개(91%)입니다. 다만 공유 폴더로 넘어온 것은 66개뿐이고 `DONE.txt`가 없어, 복사가 중간에 끊긴 것으로 보입니다.

**지금까지 찾아 고친 지름길과 맹점.** 같은 종류의 실수가 반복돼서 모아 둡니다.
1. 카메라에 차체가 찍혀 정답이 새어 나감(v1.8a, 5/48) → 카메라를 차체 밖(x=4.1)으로 옮김
2. 인식이 속도 입력에 기대 "서 있으면 정지"를 배움(v1.8d, 14/48) → 인식은 이미지만으로
3. 빨간불을 신호등이 아니라 "정지선이 보이면 빨간불"로 맞힘(v1.10, 신호등 영상을 지워도 정답률 그대로) → 빨간불은 신호등 영상에서만
4. 신호등 카메라가 낮은 신호등을 못 찍음(v1.10c, Town02 위반 31회) → 정지선 313곳 계산으로 50°/위 5° 선택
5. 전문가가 늘 같은 자리(정지선 7.2 m 앞)에 서서 모델이 "멈췄으면 7 m"를 배움(v2.0) → 정지 위치 무작위화
6. 전문가가 차 모서리가 차로 복도(중앙선 ±1.3 m) 안에 들어와야 앞차로 봐서, 그보다 넓은 차가 한가운데 있으면 못 봄(v2.2 수집, Town01 40개 중 11개 추돌) → 모서리가 복도 양쪽에 걸쳐도 앞을 막은 것으로 봄

교훈: 학습 결과가 좋아 보여도 **모델이 무엇을 보고 판단하는지**를 입력을 지우거나 바꿔 가며 확인하고, 센서가 무엇을 찍는지 직접 봐야 합니다. 정답을 다는 전문가도 똑같이 의심해야 합니다.

## 코드를 돌려 보는 법
```bash
python -m pytest -q
```
CARLA 서버(`CarlaUE4.exe -RenderOffScreen`)를 켠 뒤, 지금 쓰는 설정입니다.
```bash
python -m carlautopilot.cli.carla_run collect --carla-root <CARLA 폴더> --data-root <데이터 폴더> --town Town03_Opt --episodes 40 --seed 211 --png-compress 1 --walkers 40 --junction-rules --start-delay 2 --views 1:0,-1:0,0:10,0:-10 --light-stop 1.5:8 --path-walkers 4 [--lead-brakes 1]
python -m carlautopilot.train.train_steering --data-root <데이터 폴더> --out-dir <학습 폴더> --cache-dir <캐시 폴더> --device cuda --num-workers 4 --epochs 8 --batch-size 64 --backbone resnet18 --lr 3e-4 --amp --cosine --loss-weights 10 0.5 0.5 0.5 1 0.2 0.05 1 0.05 0.05 0.1 --predict-speed --perceive --balance-stops --boost-red-approach 3 --boost-yield 5 --light-camera [--surround]
python -m carlautopilot.cli.carla_run eval --carla-root <CARLA 폴더> --town Town02_Opt --episodes 10 --seed 100 --walkers 40 --junction-rules --model-speed 8 --event-frames [--radar] [--view] --checkpoint <학습 폴더>/checkpoint.pt --out-dir <평가 폴더>
```
- 기본값: 운전 영상 160×320, 전면 시야각 120°, 수집 간격(`--stride`) 4, 조향 잡음 0.05. `--surround`를 주면 모델 B(좌·우·후방 카메라 추가), 빼면 모델 A(전면 + 신호등 크롭).
- `--views`: 복구 시점 카메라(왼쪽 이동 m:왼쪽 회전 °). 한 스텝이 학습 행 5개(전면 + 4)가 됩니다. `--lead-brakes`는 위 알려진 문제가 고쳐질 때까지 쓰지 않습니다.
- `--radar`: 전면 레이더. 인식하는 모델은 카메라와 레이더 앞차 중 가까운 쪽을 씁니다.
- `--view`: 모델이 보는 카메라 화면과 판단을 실시간 창으로 보여 줍니다. 결과는 바뀌지 않고, 공식 평가에는 쓰지 않습니다.
- `eval`에 `--checkpoint`가 없으면 전문가를 평가합니다. 한 번에 도시 하나만 다룹니다(맵 전환은 별도 프로세스, 이유는 architecture.md).
- 평가 기록(`logs/*.jsonl`)에는 프레임마다 모델의 인식 출력(`percept`)과 다음 신호의 실제 거리·상태가 남습니다. `--event-frames`를 주면 사건 직전 4초 화면이 `frames/`에 저장됩니다.
- 수집 기록(`collect_log.jsonl`)의 충돌 주행에는 `"collision": [종류, 상대 차종]`이 남습니다.
- 설치: Python 3.12 가상환경에 `requirements.txt`, CUDA용 `torch`·`torchvision`(pytorch.org의 cu132 인덱스), `carla==0.9.16`, `networkx`.

## 확정된 결정 요약 (상세는 plan.md)
- CARLA 세단(링컨 MKZ 2020)이 본 프로젝트다. ETS2 이식은 하지 않는다(2026-10-30).
- 단계와 기준: 카메라 배치 → 수집 → 모델 A(전면)와 B(다중 카메라) → DAgger와 규칙을 학습으로 → 주차. A ≥36/48, 최종 ≥39/48.
- 카메라는 사각을 줄이되 대수는 최소로, LiDAR는 쓰지 않는다. 가까운 물체는 실차처럼 카메라 + 레이더 융합으로 보완한다(2026-11-01).
- 실패는 DAgger에 기대지 않고 원인(데이터, 센서)에서 고친다(2026-11-01).
- CARLA 0.9.16 + Python 3.12, 비공개 저장소, 집 데스크톱(RTX 4070 SUPER)과 노트북(RTX 5060 Laptop)을 함께 쓴다.
- 규칙은 땜질하지 않고 모델 판단으로 바꾼다. 속도 표지판·장애물 회피·차로 변경은 하지 않는다.
- ETS2 프로젝트의 코드는 쓸 만하면 가져온다. ETS2 데이터셋은 비상업적 연구용이라 가져오지 않는다.

## ETS2 프로젝트에서 이어받은 것
이전 프로젝트 [ets2-autopilot-learning](https://github.com/AutoPilotWorks/ets2-autopilot-learning)(비공개, 보관)에서 얻은 교훈입니다. 그 저장소의 2026-10-19 인계 문서 기준이며, 이 저장소에서 다시 검증하지 않았습니다.
- **목표 철학(사용자):** 화면만 보고 AI가 스스로 판단하는 자율주행을 만든다. 따라 하기와 규칙 덧대기로 끝내지 않고, 규칙은 하나씩 걷어내며 "모델만"으로 매번 측정한다. ACC처럼 실제 차를 흉내 낸 공학 모듈은 섞어도 되지만, 따로 떼어 나중에 학습으로 바꿀 수 있게 만든다.
- **실패에서 배운 것:** 10월 14일 벽 충돌의 원인은 모델이 아니라 **차선 보조 규칙**이 엉뚱한 선을 잡아 모델의 조향을 뒤집은 것이었다. 규칙을 넣으면 그 규칙이 오류의 원인이 될 수 있다.
- **평가에서 배운 것:** 라벨 정의가 겹치면 모델 한계처럼 보이는 오류가 생긴다. 세션 단위 교차검증과 단순한 기준선과의 비교가 필요하다.
